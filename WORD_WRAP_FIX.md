# Виправлення переносу слів

## Дата: 27 грудня 2025

## Проблема

При переносі тексту на новий рядок слова розривалися посередині замість переносу по пробілах:

**Було:**
```
...для зберігання інформації на пристрої. Відділені дані: Використовуват|
и локальної бази данихSQLite для зберігання інформації на пристрої.
```

**Стало:**
```
...для зберігання інформації на пристрої. Відділені дані: 
Використовувати локальної бази данихSQLite для зберігання інформації на пристрої.
```

## Причини проблеми

1. **Метод `FitCount` повертав неправильну позицію**
   - Включав пробіл у кінець рядка: `return i - start + 1`
   - Мало бути: `return i - start` (без пробілу)

2. **Пробіли не пропускалися на початку нового рядка**
   - Після переносу пробіл залишався на початку наступного рядка
   - Це призводило до зайвих пробілів і неправильного вирівнювання

3. **Логіка була нечітка**
   - Не обробляла випадок, коли саме на позиції розриву пробіл
   - Не гарантувала хоча б 1 символ (ризик нескінченного циклу)

## Рішення

### 1. Переписано логіку FitCount

```csharp
// Перевіряємо, чи розриваємо слово посередині
bool breakingWord = !char.IsWhiteSpace(text[end]) && 
                   (end > start && !char.IsWhiteSpace(text[end - 1]));

if (breakingWord)
{
    // Шукаємо останній пробіл перед розривом
    for (int i = end - 1; i > start; i--)
    {
        if (char.IsWhiteSpace(text[i]))
        {
            // Повертаємо позицію БЕЗ пробілу
            return i - start;
        }
    }
    
    // Немає пробілів - доведеться розірвати слово
    return Math.Max(1, best);
}
```

### 2. Додано пропуск провідних пробілів

У всіх методах (`Render`, `GetCaretLocation`, `GetCaretPositionFromPoint`):

### 3. Логіка переносу

**Алгоритм:**
1. `FitCount` знаходить максимум символів що поміщаються
2. Якщо розрив відбувається посередині слова:
   - Шукаємо останній пробіл перед розривом
   - Повертаємо позицію без включення пробілу
3. При рендерингу наступного рядка:
   - Перевіряємо, чи на позиції пробіл
   - Якщо так і це початок рядка (x==0) - пропускаємо

## Результат

✅ Слова переносяться цілком на новий рядок
✅ Немає зайвих пробілів на початку рядків
✅ Українська мова підтримується коректно
✅ Довгі слова без пробілів все ще розриваються (якщо не поміщаються)
✅ Позиціонування каретки працює правильно з урахуванням переносів
✅ При зміні розміру вікна (наприклад, на повний екран) пробіли не перетворюються на великі гапи

## Додаткове виправлення: Проблема з пробілами у повноекранному режимі

### Дата: 27 грудня 2025 (оновлення)

### Проблема

Коли текст переносився у звичайному режимі (вузьке вікно), а потім вікно розширювалося на весь екран, з'являлися великі пробіли між словами.

**Причина:**
Логіка `if (x == 0 && pos > 0 && char.IsWhiteSpace(text[pos]))` пропускала пробіли на початку візуальних рядків. Але умова `pos > 0` (не на початку тексту run) не правильно визначала, чи це справжній пробіл з тексту, чи пробіл після переносу слова.

При розширенні вікна текст, що був перенесений, повертався на один рядок, але пробіли все ще пропускалися, створюючи великі гапи.

### Рішення

Додано відстеження `isStartOfLogicalLine` - прапорець, що вказує, чи ми на початку логічного рядка (тексту між `\n`), а не просто візуального рядка після переносу.

```csharp
bool isStartOfLogicalLine = true; // На початку кожного логічного рядка

// Пропускаємо пробіл тільки якщо:
// - На початку візуального рядка (x == 0)
// - НЕ на початку логічного рядка (!isStartOfLogicalLine)
// - Символ - це пробіл
if (x == 0 && !isStartOfLogicalLine && char.IsWhiteSpace(text[pos]))
{
    pos++;
    globalDisplayIndex++;
    continue;
}

// Після рендерингу будь-якого контенту
isStartOfLogicalLine = false;
```

**Результат:** Пробіли на початку логічного рядка (справжні пробіли з тексту) завжди відображаються. Пропускаються тільки пробіли на початку перенесеного рядка (де слово було розділене).

### Оновлена логіка в методах

Зміни застосовано до трьох методів:
1. **`Render()`** - основний метод відображення тексту
2. **`GetCaretLocation()`** - визначення позиції каретки
3. **`GetCaretPositionFromPoint()`** - визначення позиції тексту за кліком миші

У кожному методі:
- Додано змінну `bool isStartOfLogicalLine = true` на початку кожного логічного рядка
- Змінено умову пропуску пробілів з `x == 0 && pos > 0` на `x == 0 && !isStartOfLogicalLine`
- Додано `isStartOfLogicalLine = false` після рендерингу будь-якого контенту або переносу рядка
