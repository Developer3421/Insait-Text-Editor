# Виправлення великих пробілів у повноекранному режимі

## Дата: 27 грудня 2025

## Проблема

При роботі з текстовим редактором виникла наступна проблема:

1. Текст вводився у звичайному режимі (вузьке вікно)
2. Слова коректно переносилися на новий рядок
3. При розширенні вікна на весь екран з'являлися **великі пробіли** між словами

### Приклад проблеми

**У вузькому вікні (коректно):**
```
Це дуже довгий текст з
українськими словами
```

**У широкому вікні (неправильно):**
```
Це дуже довгий текст з     українськими словами
                      ^^^^^
                 великий пробіл
```

## Причина проблеми

Логіка пропуску пробілів працювала так:

```csharp
// СТАРИЙ КОД (неправильний)
if (x == 0 && pos > 0 && char.IsWhiteSpace(text[pos]))
{
    // Пропускаємо пробіл на початку візуального рядка
    pos++;
    globalDisplayIndex++;
    continue;
}
```

**Проблема:** Умова `pos > 0` означала "не на початку run тексту", але це не правильно визначало, чи це:
- Справжній пробіл з оригінального тексту
- Пробіл після переносу слова

При розширенні вікна:
1. Текст, що був на двох рядках, повертався на один
2. Але пробіл на початку "другого" рядка все ще пропускався
3. Це створювало великий гап у тексті

## Рішення

Додано відстеження **логічного початку рядка** (початок тексту між `\n`, а не просто візуального рядка після переносу):

```csharp
// НОВИЙ КОД (правильний)
bool isStartOfLogicalLine = true; // На початку кожного логічного рядка

// Пропускаємо пробіл ТІЛЬКИ якщо:
// 1. На початку візуального рядка (x == 0)
// 2. НЕ на початку логічного рядка (!isStartOfLogicalLine)
// 3. Символ - це пробіл
if (x == 0 && !isStartOfLogicalLine && char.IsWhiteSpace(text[pos]))
{
    pos++;
    globalDisplayIndex++;
    continue;
}

// Після рендерингу будь-якого контенту
isStartOfLogicalLine = false;

// Після переносу рядка
if (x >= maxWidth - 0.5)
{
    y += lineHeight;
    x = 0d;
    isStartOfLogicalLine = false; // Більше не на початку логічного рядка
}
```

### Як це працює

1. **Початок логічного рядка:** `isStartOfLogicalLine = true`
   - Це рядок між `\n` символами (або початок тексту)
   - Пробіли НЕ пропускаються (це справжні пробіли з тексту)

2. **Після переносу слова:** `isStartOfLogicalLine = false`
   - Текст перенесено через обмеження ширини
   - Пробіли пропускаються (залишки переносу)

3. **При зміні розміру вікна:**
   - Якщо текст знову поміщається на один рядок
   - `isStartOfLogicalLine` залишається `true` для початку
   - Пробіл НЕ пропускається → не створюється гап

## Технічні деталі

### Визначення термінів

- **Логічний рядок (Logical Line):** Текст між символами `\n` (або від початку до першого `\n`)
- **Візуальний рядок (Visual Line):** Рядок на екрані, що може бути частиною логічного рядка після переносу через обмеження ширини
- **Перенос слова (Word Wrap):** Автоматичний перенос тексту на новий візуальний рядок при досягненні краю вікна

### Алгоритм

```
ДЛЯ КОЖНОГО логічного рядка:
    isStartOfLogicalLine = true
    
    ДЛЯ КОЖНОГО символу:
        ЯКЩО x == 0 (початок візуального рядка):
            ЯКЩО !isStartOfLogicalLine ТА символ - пробіл:
                ПРОПУСТИТИ символ
            ІНАКШЕ:
                ВІДОБРАЗИТИ символ
        
        ЯКЩО текст не поміщається:
            ПЕРЕНЕСТИ на новий рядок
            isStartOfLogicalLine = false
        
        ПІСЛЯ відображення будь-чого:
            isStartOfLogicalLine = false
```

## Висновок

Ця зміна гарантує, що логіка переносу слів працює коректно незалежно від розміру вікна, і пробіли відображаються тільки там, де вони є в оригінальному тексті.
